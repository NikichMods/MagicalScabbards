## Вопросы для решения механизма

1. Какой достаточно ранний draw-сигнал позволяет **сразу показать комплект** для поддерживаемых маршрутов, включая прерывание и случаи вне боя? Для первого удара cudgel уже есть кандидат. Для stow использовать доказанный `EquipModeChange(Sheath)` плюс **2 секунды** с guard, а не искать точный stow-animation end.
2. Какой обратимый канал подавления, кооперативный или отдельный, доступен для подтверждённого `HildaCudgel_BP_C.hilda_cudgel_sheath`? `bVisible` имеет штатного writer; `bHiddenInGame` пока кандидат, а не доказанная независимость. Pawn scabbard_a/b не включать в первый эксперимент по аналогии.
3. Как реализовать одноразовый таймер, его отмену/инвалидацию при новом draw, повторной Sheath, смене оружия/pawn, unknown и reload и rollback **только собственных записей** на том же живом компоненте?
4. Какие реальные компоненты образуют убранный комплект **вместе с оружием**, а какие — текущее оружие в руках? Доказать по owner/attachment и фактическому показу. Допускать скрытие целого составного `*_sheath`, если он относится только к убранному комплекту; section visibility изучать лишь при доказанном пересечении с активным оружием.
5. Как отслеживать поколение local pawn и актуальную экипировку без устаревших акторов, как вернуть своё состояние на interrupted/load/map transitions?

## Метод и стоп-условие

Повторно используйте сохранённый static bytecode/evidence и локальные runtime-логи. Только при реальном пробеле подготовьте **один bounded read-only UE4SS observer** на verified local pawn и одном оружейном семействе, с заранее проверенными callback, budget, failure/cleanup и hash source. Никаких глобальных поисков на каждом кадре. Игра запускается/перезапускается **только с разрешения пользователя**. Не изменять visibility, меши, assets, VFX, сохранения или соседние моды.

**Остановить** шаг при подтверждении раннего draw для узкого сценария, Sheath commit, безопасного взаимодействия с writer и rollback и guard для 2-секундного timer (или доказанном блокере) с reviewable READY/BLOCKED. Новые reusable game facts — в Asterigos-Research, специфика и доказательства — в MagicalScabbards. Write-test hide/show и VFX только отдельными следующими этапами после нужных gates.

### Протокол и контроль записи

1. **Допуск.** Один мир, один живой локальный pawn, один уже выбранный обычный cudgel и маршрут draw через первый обычный удар. Без смены оружия, reload, карты или кат-сцены как части сценария. Сначала снять stock цикл в том же сеансе до вооружения теста: `BeginDoSkill` pre `hilda_cudgel_atk1_idle` до переноса, `EquipModeChange` и доставки обеих штатных записей sheath. Сверить известную identity и флаги. При расхождении запись не вооружать.
2. **Hide.** После свежего штатного Sheath post (аргумент 1, сокет `scabbard_a`, main=false / sheath=true) поставить одноразовые 2000 мс. На expiry сначала потребить актуальный токен, затем заново разрешить тот же pawn/world, actor, два компонента и точный stock asset, owner/root attachment, сокет, устойчивое `equipMode=1`, main=false / sheath=true и отсутствие новой фазы. Требовать vanilla hidden=false на цели. Записать только `SetVisibility(false, false)` на точном `_sheath`, подтвердить readback и held main без изменений. Действия на игровом потоке, без propagation. Собственная транзакция помечается до вызова, чтобы наблюдение setter не приняло её за чужую; частичный сбой сверяется по живому состоянию перед cleanup.
3. **Show и передача владения.** Ранний pre сначала инвалидирует попытку, затем синхронно возвращает true, пока этот самый компонент ещё в подтверждённом стыке Sheath. Только если false записан тестом и после этого не было штатного или чужого запроса. Штатный `SetVisibility` на точном sheath, даже если запрашивает текущее значение, прекращает наше владение. Его не блокировать, не исправлять и не восстанавливать сохранённый true поверх него. InHand/Floating и неожиданные записи прекращают экспериментальный hide. Нативные обходы reflected hook остаются пределом покрытия; при неожиданном readback остановка, без автоматического повторного скрытия.
4. **STOP и аварийная граница.** Инвалидировать токен до отмены handle, запретить новые записи. Если цель та же, ещё stowed и владение доказано, вернуть исходный true и сверить readback. После штатной передачи — оставить значение игры и сверить её commit. Если identity устарела, никуда не переносить snapshot. Неизвестный живой объект или неоднозначное владение → остановка с `CLEANUP_PENDING`, без слепого true и без выгрузки в живом процессе. Заранее оговорённый предел такого сеанса — ручной выход из игры, если безопасный release невозможен. Destroy завершает владение без записи по старому объекту. При любом lifecycle-сигнале инвалидировать попытку, при expiry повторно проверять identity даже после успешной отмены.
5. **Проверка.** До игры на стабе показать no-op старого callback после cancel, повторного Sheath и смены поколения, отказ на неверном socket/owner/asset, отсутствие чужой записи при STOP и обработку same-value штатной записи. В игре после baseline: stow → выдержать 2 с → убедиться, что исчез только убранный комплект; draw → проверить ранний возврат и штатное оружие в руке; stow → draw до дедлайна → убедиться, что старый callback ничего не сделал. Затем свежий stow, дождаться hide и нажать STOP, чтобы визуально и по readback подтвердить возврат исходной видимости. Записать порядок event/token/readback и CLEANED. Любое раннее/лишнее скрытие, задержка show, расхождение vanilla или неопределённый rollback — провал теста. Точность первого кадра и фактическое отсутствие дубля проверяются здесь, из предыдущих логов не предполагаются.

READY ограниченного теста опирается на точного владельца, подтверждённый канал и воспроизводимую штатную перезапись. Объект вмешательства и область отката ограничены одним компонентом и одним сценарием. Широкий lifecycle, другие draw-маршруты, остальные детали комплекта и production-совместимость остаются открыты. Следующий шаг после отдельного разрешения — подготовить и прогнать этот кандидат по протоколу, без нового read-only сеанса ради повторения 03/05.

1. При закрытой игре установить один точный кандидат; запустить игру вручную. Уже выбранный обычный молот, полностью убран. **Ctrl+Alt+F9** начинает baseline. 2. Первый удар → убрать → выждать 2 секунды. Проверить скрытие только комплекса молота. Следующий удар должен сразу вернуть его и оставить оружие в руке штатным. Убрать и вновь вынуть до дедлайна, проверить отмену.
3. Снова убрать, дождаться скрытия и нажать **Ctrl+Alt+F10**. Проверить возврат и `CLEANED`. При аномалии нажать STOP. При `CLEANUP_PENDING` закрыть игру вручную, не выгружать кандидат в живом процессе. Защитный предел 120 с с начала baseline; клавиши и lifecycle callback инертны после остановки.
