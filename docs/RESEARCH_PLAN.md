## Следующий игровой gate

[Отмена уже поставленного таймера — игровой PASS](SCABBARD_DYNAMIC_CUDGEL_13.md#игровой-pass-отмены-уже-поставленного-таймера--2026-11-08). Принятые визуальный сеанс и отмену таймера повторять не нужно.

[scabbard-freeplay-01](SCABBARD_FREEPLAY_14.md) подтвердил в игре доставку уведомления о смене слота, восстановление диагностики после reload и STOP. Для проверенной смены Blueprint post уже поздний для всей старой группы. Автоматическая запись при свободной игре BLOCKED.

[scabbard-universal-01](SCABBARD_UNIVERSAL_15.md#игровой-сеанс-2026-11-08) подтвердил, что все шесть привязок сохраняются в EndPlayPre при одной смене оружия, включая компонент завершающегося актора. При reload наблюдатель сбросил старый снимок, повторная привязка до STOP в этом сеансе не зафиксирована.

[scabbard-endplay-release-01](SCABBARD_ENDPLAY_RELEASE_16.md#игровой-результат-2026-11-08) подтвердил синхронный release двух компонентов Хильды внутри EndPlayPre при смене молота на парные клинки, с pre/post, readback и успешным STOP. Уходящие компоненты ещё разрешались по старой identity после смены, без прежней привязки. Для расширения маски нужно выяснить их дальнейшее выбытие или повторное использование. Синхронный release двух деталей на том же маршруте повторять не требуется.

[scabbard-equipment-lifetime-01](SCABBARD_EQUIPMENT_LIFETIME_17.md#игровой-сеанс-2026-11-08) подтвердил `Destroyed` у обоих владельцев и новые экземпляры при обратной смене. Старые ещё разрешались вне комплекта. K2 pre не наблюдались, а EndPlayPre уже был внутри уничтожения. Следующий gate для маски на уходящих акторах — безопасная граница до уничтожения либо доказанный безопасный выход из комплекта с собственной маской без записи в уходящий объект.

По принятому решению этот gate проверяется в одном [интегрированном кандидате](SCABBARD_INTEGRATED_18.md) без отдельного write-test уходящего актора. Рабочая гипотеза — подтверждённо уничтожаемый владелец уходит из отображения, а его заменитель не наследует маску. Проверка включает реальный hide/show и смену с активной маской. Откат на живых целях, retirement при Destroyed и неопределённый lifecycle логируются отдельно.

[Integrated 02](SCABBARD_INTEGRATED_19.md#игровой-сеанс-2026-11-08) подтвердил hide/show посоха и Sheath клинков. Следующий сеанс — [Integrated 03](SCABBARD_INTEGRATED_20.md): идентифицировать оставшуюся слева деталь и проверить восстановление после замены клинков с оружием в руках. Отдельные уже успешные прогоны не повторять.

**Следующий шаг после Integrated 03 — [Integrated 04](SCABBARD_INTEGRATED_21.md).** Единственной отклонённой целью при hide клинков был hilda_staff_unuse (Inventory 2, на scabbard_b), а после замены с клинками в руках stock Sheath нового актора был доставлен, но отвергнут как actor-untracked. Пользователь принял сильного кандидата на остаток без отдельного визуального A/B и согласовал расширение на все 15 stock assets по структурной роли. Нельзя считать *_use исключительно held-мешем: это может быть оформление на ножнах. Вместо восьми отдельных экспериментов — один общий классификатор и один интеграционный игровой прогон. Второй gate — восстановить hide при переходе через меню без новой атаки. До технической проверки исходников, офлайн-инвариантов и игрового прогона production остаётся BLOCKED.

**Решение после [Integrated 04, игровой сеанс 2026-11-09](SCABBARD_INTEGRATED_21.md#игровой-сеанс-2026-11-09):** готовность частичная. Полный визуальный PASS комплекта клинки + молот и возврата всех шести целей принят для этой конфигурации; `hilda_staff_unuse` устранил прежний остаток. Не повторять визуальную изоляцию или этот PASS без конкретной регрессии.

**Следующая задача для локального Codex — два адресных исправления в новом исследовательском кандидате, без установки в игру:**

1. **Menu Sheath:** после подтверждённого `EquipModeChange(Sheath)` нового актора сохранить прежнюю identity/pawn generation и исходную двухсекундную границу. По достижении `>=2000 ms`, если единственная ожидаемая преграда — старый локальный drawn-актор, ещё не завершивший equipment lifecycle, сохранить именно статус «задержка истекла, ждём штатный event», не запускать повторно задержку и не скрывать. На соответствующем EndPlay/slot event `refresh` попробовать ровно одну новую проверку текущего actor, held, generation, root/socket, stable stowed и отсутствия новых skills. Любая новая атака, чужой transition, смена цели, неудостоверяемая причина guard, reload, STOP или изменение identity отменяют ожидание. Не перепроверять покадрово, не считать сам EndPlay доказательством stowed. Логи должны различать `WAIT_OLD_ACTOR` и фактическое `HIDDEN`/отказ. Проверить и сценарий, когда old EndPlay происходит **до** 2-секундной границы.
2. **Staff switch:** в `BeginDoSkill` отдельно распознавать реально наблюдённый `hilda_staff_atk1` наряду с `hilda_staff_atk1_idle`; ставить семейную `drawPending=staff` только при точном подтверждении нового локального stowed `HildaStaff_BP_C`, а не по одному названию. После штатного InHand post именно этого актора очищать защёлку и принимать затем настоящий Sheath; неизвестные skills не должны автоматически разрешать hide. Обычные удары уже вынутым посохом не должны создавать вечный `drawPending`.

Перед передачей нового кандидата исполнить Lua 5.4 stub для новых событий, порядка «таймер до EndPlay», «EndPlay до таймера», new draw / stale callback / STOP, противоположных акторов и неизвестных skills; оставить frozen Integrated 04 (`888e0d9`) без изменений. Следующее игровое испытание — один интеграционный прогон двух ранее проваленных маршрутов и быстрый STOP; другая экипировка, startup pickup, reload и дополнительные визуальные наборы остаются отдельными acceptance-вопросами.

Проверки роли `*_use/_unuse` и раннего draw для других семейств нужны для общей маски. Совместимость с CombatHUD/HildaSoftLight/косметическими пакетами и локальный магический VFX проверяются отдельно. Не вводить CI, VERSION, installable artifact или Release без production-механизма и соответствующих gates. Нумерованные/переданные кандидаты неизменяемы.
