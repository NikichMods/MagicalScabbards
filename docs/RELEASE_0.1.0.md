# MagicalScabbards 0.1.0 — принятая релизная база

**Решение 2026-11-19:** пользователь принял `0.1.0-test.1` после двух игровых сеансов и разрешил полноценный первый стабильный релиз без повторения матрицы оружия. Релизная база игрового кандидата: `dddd75b6195376521fb8aab9dedeb1232e5f9005`; первоначальный тестовый ZIP SHA-256 `ea512b7484850ba78d41089abf707c1af233b780ef001f052b7163dd568fb6e1` (не заменять, не переименовывать в v0.1.0).

## Статус и пределы доказательства

- Тестовый source `dddd75b`: Windows/UE4SS автоматический START; 21 hide с 6/7 целями; представительные сочетания всех шести типов; draw/stow, смены, Bracer, reload, ручной F8, restart и дальнейший hide. Пользователь принял визуальную полноту и своевременность без покадрового анализа.
- Основной игровой сеанс: [история и частичный финал](RELEASE_CANDIDATE_01.md#игровой-сеанс-2026-11-19--partial-pass-финальная-очистка-не-подтверждена). Необъяснённое `CLEANUP_PENDING owner-ended` для `HildaSpear_Unuse_BP_C.SkeletalMesh` непосредственно перед закрытием процесса; второе `CLEANED` не было записано.
- Адресный игровой сеанс на **том же неизменённом кандидате**: [STOP/restart/STOP PASS](RELEASE_CANDIDATE_01.md#адресный-сеанс-stoprestartstop-2026-11-19--pass); два `CLEANED`, отсутствие hide после STOP, повторное скрытие по новому трёхсекундному окну. Исходную причину `owner-ended` этот опыт не доказывает и не отменяет.
- CI ранее: [первичный прогон тестового источника](https://github.com/NikichMods/MagicalScabbards/actions/runs/44004650164) — SUCCESS. Для стабильного пакета CI обязан повторить Lua 5.4 и проверить идентичность `v0.1.0`/версии в коде/ZIP/manifest/checksum до выдачи Release.
- **Граница приёмки:** штатная игра не позволяет оставить Bracer-only как обычный выбранный loadout; `5/7` и `7/5` прошли Lua-модель, не требуют отдельного игрового теста. Не заявлять все перестановки, не проверенные в игре, или совместимость с любыми косметическими модами.

## READY-гейт стабилизации

**Изменяемое свойство:** идентификатор/распространение `v0.1.0`, не сам алгоритм hide/show. Владелец версии — `Scripts/main.lua:local VERSION`. Конечные потребители — диагностический префикс UE4SS, файл ZIP, embedded manifest, релизный tag и Release. Зона воздействия — статический идентификатор и пакет; `Scripts/{equipment,outgoing,reconcile,visibility}.lua` остаются побайтно исходными из Bracer 03; `main.lua` отличается от `dddd75b` только строкой `VERSION`. Подтверждение — автоматические тесты Lua 5.4, сравнение исходников и воспроизводимый CI ZIP на **точном source commit v0.1.0**, manifest/readback и конечный Release asset. Никаких новых механик, VFX или FSM.

**Решение:** READY для упаковки и stable promotion на основании принятого пользовательского объёма; стабильный ZIP имеет собственные байты и source SHA, поэтому не выдавать его за идентичный тестовому архиву. Реальное повторное испытание каждой комбинации не требуется, поскольку поведение не менялось.

## Ограничения публичной v0.1.0

- Целевой хост: Asterigos Steam 1.09 (build 12996889), UE4.27, Windows x64, UE4SS 3.0.1-1181-g83330635. Иные версии — вне подтверждённого объёма.
- `Ctrl+Alt+F8` — **необязательное** выключение/повторное включение в текущем игровом процессе. Нажимать перед обычным выходом из игры не требуется. `enabled.txt` делает запуск автоматическим. Hot reload Lua/замена файлов во время игры не поддерживается.
- Установленная причина единственного `owner-ended` **неизвестна**. Нельзя утверждать автоматический rollback на стадии shutdown, но воспроизведённого визуального дефекта в продолжающейся игре нет. При появлении такого дефекта — адресная диагностика по полному логу и состоянию оружия.
- Избыточная непрерывность ножен при смене через меню, исключение Bracer из generic pre и магический VFX — отложенные косметические улучшения, не блокеры базовой v0.1.0.
- В Release размещать исходный ZIP с `manifest.json` и checksum, собранный из точного `v0.1.0` source commit. Источники — оригинальный MPL-2.0 код, без чужих pak/uasset/UE4SS.
