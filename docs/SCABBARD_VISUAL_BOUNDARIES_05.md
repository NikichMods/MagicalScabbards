## Метод и критерий визуального сопоставления

Один цикл: уже выбранный stock cudgel, устойчивый stowed → первый обычный удар → устойчиво в руке → штатное убирание → устойчивый stowed. Ctrl+Alt+F9 на трёх устойчивых состояниях. На третьем снимке завершение, Ctrl+Alt+F10 — досрочная остановка. В этом сеансе достаточно одного маршрута первого удара. Не требуется специально вызывать смену оружия, reload или боевую последовательность.

Для A/B необходима **независимая визуальная сверка**. Предпочтительно в коротком видео видеть Хильду и диагностические строки журнала рядом, вне игрового HUD. Использовать один источник записи для обеих областей; смотреть момент начала/конца движения по изображению и номера событий по строкам `BEGIN_PRE` и `EQUIP_POST`. Учитывать буферизацию log tail, частоту записи и задержку вывода. Появление строки раньше первого движения с различимым запасом даёт верхнюю границу времени A. Для B появление строки позже движения само по себе не доказывает, что callback был поздним: нужен общий измеримый допуск синхронизации. Если визуальная запись недоступна или границы попали в интервал неопределённости, отчёт фиксирует только socket/flags и оставляет визуальный gate BLOCKED. Наблюдение на глаз полезно для идентификации стадий, но не превращает раздельные источники в покадровое доказательство.

Observer привязывает точный локальный pawn через единственный viewport HUD, один cudgel с проверенным owner, два компонента и точный anim instance. `BeginDoSkill` pre захватывает имя до фильтрации и читает точный actor по проверенному пути. EquipModeChange Blueprint post логирует доставку до enum decode. Native hidden hook быстро отсекает прочие адреса, пишет только target и два известных control slots. В callback остаются только строки/скаляры между вызовами. Поиск по классам происходит на ручных снимках, без per-frame обхода. Верхние пределы: три снимка, 24 целевых события, 1024 входа глобального hidden hook, защитный 120-секундный предел для цикла, который в предыдущем запуске занял около 9 секунд. При исчерпании бюджета или ошибке прекращается чтение, cleanup снимает hooks или явно оставляет `CLEANUP_PENDING` до закрытия процесса.

Lua 5.4: синтаксис, ранний Begin, поздний Equip, target/control hidden, отбрасывание чужого объекта, неверный enum, лимит global dispatch, остановка и cleanup проверены на стабах. Фактическую доставку hidden seam и синхронизацию стобы не подтверждают. Перед запуском сверить установленный hash, после сеанса сохранить приватный лог, его SHA-256 и границы захвата.

## Решение о следующем тесте

READY возможен только для подтверждённого маршрута первого удара и одного текущего `hilda_cudgel_sheath`, если A происходит до визуального draw, B на или после визуального конца stow, а C даёт основание владеть временным подавлением и восстанавливать только собственную запись на том же живом компоненте. Снимок исходного hidden=false не даёт владения при конкурирующем writer. Другие владельцы, held mesh, `_Use/_Unuse` и pawn-компоненты не входят в маску. При потере identity или неопределённом писателе write-test остаётся BLOCKED.
