## Источник состояния

Адресная проверка EXE Steam 12996889 через существующий PE/Capstone reader, SHA-256 `ddea6b5ca5d34836f01702993d20209c2595367287e6cd5a135a7ace1958b1c0`. Адреса — RVA. Имена и сигнатуры сверены с игровыми `GameGlobal.h`, `EInUseWeaponIndex.h`, `EWeaponType.h` и `ECharacterEquipmentObjectSlot.h`.

| Reflected API | Подтверждение в native |
| --- | --- |
| `GetInUseWeaponType(Character, index)` | Thunk `0x1272100` → `0x110bc80` → `0x114b7d0` → `0x11f6840` читает байты `+0x200/+0x201` структуры по `Character+0x558` для двух in-use слотов. |
| `GetInHandWeaponType(Character)` | `0x1271fa0` → `0x110bba0` → `0x114b730` читает `+0x228` той же структуры. `None=7`. `0x11f8080` сравнивает этот байт и оба слота, выбирая InHand, Sheath или Inventory перед общим consumer `0x11f79f0`. |
| `GetWeaponObject(Character, type, slot)` | `0x127c620` → `0x110e530` → `0x114d740` → `0x11f6890` на том же native state ищет `left_hand` / `right_hand` в записях выбранного семейства. Возврат через `0x11f6770` разрешает ссылку актора из записи. Сам lookup по типу может вернуть актор другого состояния, поэтому используется вместе с двумя in-use слотами. |

`PlayerEquipment.OnSettingEquip` остаётся событием инвалидации, из него не выводится текущий экземпляр. Состояние читает штатный `GameGlobal` CDO через отражённые методы. Путь CDO известен по соседним модам, но конкретные Lua-вызовы этих трёх getters и соответствие hand slot реальным stock-акторам требуют проверки в игре. При недоступном API, неожиданном enum или неподтверждённой identity запись не разрешается.

## Механизм

Обычный Sheath и Sheath через меню создают одно ожидание с идентичностями входящего комплекта и одним таймером. После 2000 мс `canHideNow` требует, чтобы точный актор входил в актуальный native набор, hand был None, известные выбранные акторы подтвердили stowed и held-меши были скрыты. Для клинков нужны обе руки. Прежние известные акторы проверяются на видимый held, пока они прикреплены к текущей Хильде. Старый экземпляр с прежним mode=InHand может остаться в памяти без блокировки, если штатный набор его уже исключил и видимого held у него нет.

Переходное состояние даёт повторный one-shot через 250 мс, максимум 24 повтора в пределах дополнительного окна 6 с. Есть также грубый wall-clock предел от первой проверки. Интервал выбран для исследовательского прогона, где разница между дедлайном и поздним refresh в Integrated 05 была около 1,79 с. Полный каталог не собирается на повторах. Остаются событийно вызванная инвентаризация, снимок подтверждённого обычного Sheath и пересборка перед записью. Проверки токена, поколения и конкретной попытки отсекают устаревшие callbacks. EndPlay может обновить контекст и снять или пометить маски, но сам не продолжает ожидание и не разрешает hide.

Владение SetVisibility, каталог 15, release на раннем draw и принятый маршрут молот → посох второй кнопкой переиспользованы. Экспериментальные переходы остаются ограничены обычным молотом, посохом и клинками. Неподтверждённая экипировка ограничивает запись.

## Проверки и игровой gate

Lua 5.4 через Lupa, `lua stub.lua Scripts/main.lua`. Прошли меню без новой атаки, старый видимый held и старый живой актор с устаревшим mode=InHand, стабилизация без EndPlay, оба порядка EndPlay, тайм-аут, один активный таймер, замена Sheath и identity, draw, старый callback, новый pawn, STOP, reload, чужой writer, rollback, молот → посох, `hilda_staff_unuse` и ground/held. Frozen Integrated 05 и 04 прошли неизменённые stubs.

После отдельного разрешения на установку **Ctrl+Alt+F7**. С клинками в руках заменить их посохом через меню и вернуться в игру без атаки. Проверить отсутствие скрытия до завершения перехода и hide после него. Затем один цикл молот → посох второй кнопкой проверяет новый guard на уже принятом маршруте. **Ctrl+Alt+F8** завершает с `CLEANED`. Оценка результата требует журнала getters/guards и визуальной проверки оружия в руках. Самостоятельная установка или production этим PASS не разрешены.
