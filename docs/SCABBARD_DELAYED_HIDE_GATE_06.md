## Отдельные биты и предел доказательства

На Steam build 12996889 / UE4.27 UHT `SceneComponent.h` объявляет два отдельных флага и два setter с аргументом propagation. Адресно проверены **только эти два setter** существующим PE/Capstone reader. SHA-256 установленного EXE `ddea6b5ca5d34836f01702993d20209c2595367287e6cd5a135a7ace1958b1c0`. Адреса — RVA этого файла.

| Штатный API | Reflected thunk → native body | Запись на целевом компоненте |
| --- | --- | --- |
| `SceneComponent:SetVisibility` | `0x33c16b0 → 0x2cea080` | на `0x2cea0e3`: `component+0x14c`, маска `0x20` |
| `SceneComponent:SetHiddenInGame` | `0x33c1440 → 0x2ce7cb0` | на `0x2ce7d13`: `component+0x14d`, маска `0x04` |

Оба тела при смене своего бита вызывают собственную виртуальную нотификацию. В hidden thunk false передаётся в native как enum 1, true как 2. В body enum 1 при смене значения допускает обход детей для обновления рендера, но ветка записи дочернего hidden относится к enum 2. Поэтому `SetHiddenInGame(value, false)` ограничивает изменение **флага** целевым компонентом. У штатного `EquipModeChange` на cudgel уже доказаны записи `bVisible` без propagation. Следовательно его две известные записи не затирают hidden-бит. Это разделение памяти и setter, а не доказательство фактической отрисовки или эксклюзивного владения hidden.

В сохранённых cooked `HildaCudgel_BP` и `BaseEquipment_BP` прямого hidden writer на sheath не найдено; у pawn `scabbard_a/b` writer доказан, эти компоненты из теста исключены. У observer 05 было 6 входов reflected hidden hook, ни одного на точном sheath или контрольных pawn-компонентах. Отдельная native ветка обходит reflected hook, включая запись через propagation. Даже чужой запрос true при уже установленном true может обозначать передачу владения, хотя setter не выполнит store. Поэтому readback true и сравнение с последней собственной записью не разрешают очистить флаг. [Справка UE по SetHiddenInGame](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/USceneComponent/SetHiddenInGame) · [SetVisibility](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/USceneComponent/SetVisibility)

## Одноразовая политика

UE4SS `ExecuteInGameThreadWithDelay(2000, callback)` с отдельным handle, `CancelDelayedAction` и проверка валидности уже имеют локальный прецедент на 83330635 в HildaSoftLight pointlight-runtime. В observer 05 проверено планирование защитного таймера, но не истечение двух секунд. Все решения и возможные записи в будущем тесте — на игровом потоке. [API delayed actions](https://docs.ue4ss.com/dev/lua-api/global-functions/delayedactions.html)

| Вход | Переход |
| --- | --- |
| Sheath post с аргументом 1, валидные owner/socket/flags | Сначала инвалидировать прошлое поколение и отменить его handle. Поставить одну попытку с новым токеном. Внутри post брать режим из аргумента, поле ещё может отставать. |
| Ранний draw на подтверждённом маршруте | Сначала инвалидировать токен и снять собственную маску на том же живом компоненте синхронно, до передачи управления штатному draw. Отменить handle. |
| Новый non-Sheath commit, смена экипировки, interruption/unknown, EndPlay, смена pawn/world, STOP | Инвалидировать токен и отменить handle. Если маска ещё наша и исходный объект жив, выполнить безопасный release. При уничтожении объекта закрыть запись владения без обращения к нему. При живом объекте без безопасного release состояние — cleanup pending. |
| Истечение таймера | Просроченный токен выходит до любого UE-доступа. Актуальную попытку потребить один раз. Заново получить текущие объекты, проверить состояние, при любом разрыве закончить без записи и повторов. |

Токен меняется **до** попытки отмены. Даже если старый callback уже был поставлен в очередь или отмена вернула false, он не вправе очищать handle нового таймера или обращаться к UE. При неожиданно сохранившемся handle не активировать новый write-сеанс до штатной остановки. На expiry проверить текущее игровое поколение, локальный pawn/world, единственный актуальный обычный `HildaCudgel_BP_C`, owner и root attachment к его `CharacterMesh0`, `scabbard_a`, `equipMode=1`, main visible=false / sheath visible=true, точный sheath asset и отсутствие нового draw/смены. Сравнить идентичность с начальной записью, включая поколение и проверяемую непрерывность жизни объектов. Адрес или имя поодиночке не дают защиты от повторного использования. Callback хранит токен и идентификаторы, без сырых UObject wrappers. На недоступном lifecycle seam не активировать запись; проверка expiry — дополнительная защита, а не замена своевременному release.

## Условный rollback и границы теста

Единственная цель — штатный `HildaCudgel_BP_C.hilda_cudgel_sheath`, содержащий весь убранный комплект. Основной held mesh, `_Use/_Unuse`, pawn scabbards и actor-wide hide исключены. Запись можно будет рассматривать только при hidden=false и доказуемом владении на этом точном инстансе. Переход false→true без propagation и readback должны подтвердить применение маски. Release только своего true→false на той же живой identity, с readback. Чужая запись или запрос того же значения отменяют владение. Не переносить snapshot на новый pawn/компонент, не форсировать false, не трогать штатный `bVisible`. При штатном STOP сначала инвалидировать таймер и дождаться явного CLEANED; при неопределённости не объявлять успешный rollback. Отключение/выгрузка допускается только после освобождения собственной маски либо завершения процесса.

Инженерный gate: цель, подтверждённый owner и blast radius узкого кандидата определены. Известный writer `bVisible` отделён, а финальные writers и владение hidden пока открыты. При будущем разрешённом тесте отдельные проверки — show на раннем draw, no-op при новом draw до дедлайна, один hide после свежего Sheath и двух секунд, отсутствие изменений held mesh и соседей, STOP возвращает исходный флаг. Сначала детерминированно проверить stale callback, повторный Sheath, потерю identity и отмену в стабе. Это план проверки, не выполненная реализация.

**Одно следующее действие:** отдельно согласовать один bounded read-only native trace на этом же cudgel, от stowed через первый удар и Sheath до конца двухсекундного окна, с read-only проверкой окончания владельца при выходе из сценария. Наблюдать обращения к hidden-setter на точном компоненте (включая запрос того же значения) и записи в байт `+0x14d` с декодированием `0x04`, чтобы поймать прямые и propagated stores. Например, аппаратная точка на entry и data watchpoint на верифицированной live identity, без подмены инструкции/значения. Заранее проверить доставку на естественном штатном контрольном writer и очистить точки при смене поколения. Это один trace, а не ещё один reflected observer. Учитывать его покрытие: отсутствие перехваченных записей без валидного контроля, или неоднозначный lifetime, оставляет BLOCKED. Статика на этом завершена; игра не запускалась, код write-test не создавался.
