## Вердикт

**READY для ограниченного пользовательского визуального результата test.3**: пользователь принял обычный перекат, последующую атаку и внешний вид Staff cast spark. В журнале четыре запуска с `scale=0.60`, `CustomTimeDilation=0.5`, `cutoff=1500 мс`. Отсутствие заметной разницы при изменении `Color` — причина **не расширять** исследование цвета сейчас, а не доказательство безвредности всех параметров.

**NOT READY для публичной `v0.1.1` из текущего HEAD**: ниже есть конкретные препятствия упаковке и неподтверждённые границы функционального объёма. Не интерпретировать принятие одной игровой связки как разрешение публиковать полный магический эффект всех семейств.

## Аудит «хвостов» и безопасный размер изменений

- **Оставить стабильный hide/show без переписывания.** `main.lua` добавил ранний VFX и классификацию четырёх точных чистых движений; `reconcile.lua` сохранил пороги 2900/3000 мс, `visibility.lua` / `outgoing.lua` не менялись относительно main. Массовый рефакторинг их lease/writer/rollback перед выпуском повышает риск и потребует повторять обширную игровую матрицу.
- **`vfx.lua` компактный и изолированный** (111 строк на audited HEAD): один собственный PSC, checked attach, проверка класса, watchdog, cleanup on stop/map/end-play, отсутствие требуемого ассета не блокирует базовое скрытие. Сохранить эту изоляцию.
- **Под вопросом только исследовательская связка `ModRef:GetSharedVariable`** из VFX Browser. Это необязательная настройка перед запуском с fallback на принятые дефолты; наблюдаемое в игре событие `settings=browser` пока не подтверждено. Если browser не будет поставляться пользователям и выпуск должен быть фиксированным, безопаснее удалить этот research-only consumer **в новом тестовом кандидате** и проверить сохранение дефолтного результата. Если живую настройку намеренно поддерживать, сначала отдельно подтвердить end-to-end; не называть её функциональностью релиза по offline-модели.
- **Диагностическая `DODGE`-запись** на первом occurrence конкретного имени за сессию допустима: её полезно сохранить для поддержки. `DEBUG_LOGGING=false`, логирование наблюдений ограничено; любой новый LOG-on-every-tick — отдельная ошибка.
- **Исследовательские папки** `research/*` и browser не должны входить в release ZIP; удалять их из Git ради «чистоты» не нужно. Оставить их как доказательства. README/требования всё ещё содержат исторический визуальный ориентир ~0.3–0.4 с, без света окружения и обеих фаз; для узкого принятого Staff-spark (1500 мс и принятый штатный свет) необходимо **явно зафиксировать отклонение/обновлённый scope**, а не править историю задним числом.

## Минимальный план продвижения

1. **Уточнить функциональную границу `0.1.1`**: узкий Staff-only эффект исчезновения + сохранение ножен при обычном уклонении, либо полная двусторонняя магия для всех семейств. Текущий `test.3` покрывает **только первый вариант**, да и в нём остаются некоторые runtime/packaging gates.
2. Для узкого варианта сначала устранить packager/manifest/test version gates **без изменения уже принятых runtime-механик**; выполнить полный Lua 5.4 regression, deterministic ZIP audit и CI на точном коммите. Не объявлять `Check research VFX browser` эквивалентом full candidate/release checks: текущая ветка получает в основном этот узкий workflow.
3. Один **короткий адресный** игровой проход без research browser с холодного старта: эффект и длительность на посохе, обычный быстрый шаг → атака; остановка при активном VFX/смена карты — по необходимости для changed VFX lifecycle. Не повторять шесть базовых семейств `v0.1.0` без конкретного сигнала регрессии; одно не-Staff сочетание для контроля отсутствия скрытого эффекта достаточно.
4. Сопоставить точный тестовый источник, installed SHA и релизный источник; после принятия нового scope создать immutable `v0.1.1` с отдельными release notes/manifest/source commit. Никакого автоматического merge/publish только по этому аудиту.

**Решение этого аудита:** source/readiness review завершён, **никаких production edits и релизных версий**. Реальный инженерный долг здесь — в packaging/version pin и неопределённом объёме релизного эффекта, не в масштабной перестройке hide/show.
