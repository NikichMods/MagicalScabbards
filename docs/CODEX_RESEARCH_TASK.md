# Codex — MagicalScabbards: ранний draw, конец stow и независимость маски (read-only)

**Готовое задание для отдельного запуска пользователем.** База продуктового контракта: `main` (на момент подготовки `685100fea5749979c9a5eaedf254151518d04723`), актуальный `AGENTS.md` и `docs/REQUIREMENTS.md`. Последнее исследование: [`SCABBARD_DRAW_BOUNDARIES_04.md`](https://github.com/NikichMods/MagicalScabbards/blob/5b2e60e0e571788afdfd76969d2a975dbc25cdeb/docs/SCABBARD_DRAW_BOUNDARIES_04.md), ветка `research/scabbard-draw-boundaries-04`. Не повторять завершённую статическую дизассемблерную работу.

## Что уже доказано

- `set weapon in hand` вызывает native handler `0x11c4d50`, который через `0x1151850` приводит к общему equipment consumer; timeline проходит в обход двух одноимённых reflected thunk. Поэтому перехват `GameGlobal:SetWeaponInHand` сам по себе не подтверждает доставку timeline-событий.
- Штатный cudgel меняет socket, затем Blueprint `EquipModeChange` выставляет `bVisible` обоих мешей. `EquipModeChange(Sheath)` post = **commit экипировки**, но не доказанный последний видимый кадр убирания.
- Для первого удара, вызвавшего draw, `hilda_cudgel_atk1_idle` и `hilda_cudgel_switch_enter` используют `cudgel_in_hand` с командой переноса на ключе 5. Наблюдавшийся `BeginDoSkill` pre с pending `hilda_cudgel_atk1_idle` — **кандидат** на раннее снятие подавления, не подтверждённый по визуальному времени. Убирание в предыдущем цикле не сопровождалось Begin/End.
- Для узкого теста кандидат — только актуальный `HildaCudgel_BP_C.hilda_cudgel_sheath` (весь убранный комплект). Не основной меш оружия в руках, не `_Use/_Unuse` и не pawn `scabbard_a/b`. `bVisible` у cudgel имеет доказанного штатного writer; `bHiddenInGame` — **непроверенная независимая маска**, не готовый production-канал.
- Общий переносимый результат в [Asterigos-Research `71ea8ec`](https://github.com/NikichMods/Asterigos-Research/commit/71ea8ec04fbca5b4c0f805aee35835a30216d45e).

## Три проверяемых вопроса

**A — раннее появление.** На уже выбранном stock cudgel, устойчивое stowed → обычный первый удар, сопоставить доставленный `BeginDoSkill` pre с `pending=hilda_cudgel_atk1_idle` с текущим **socket и видимостью** и независимым визуальным началом извлечения. Доказать или опровергнуть, происходит ли он **до первого видимого движения** и до native hand-placement commit. Успех только на первом ударе не устанавливает применимость к выниманию без удара, переключению оружия и прерываниям — явно пометить эти границы. Если имеется простой штатный путь ручного извлечения без удара, проверить его в том же разрешённом сеансе, но не превращать это в новую матрицу всего оружия.

**B — позднее исчезновение.** На том же акторе после draw наблюдать `EquipModeChange(Sheath)` **post** с новым аргументом enum, `scabbard_a`, `main.bVisible=false`, `_sheath.bVisible=true` и сопоставить с последним **видимым кадром** убирания. `Floating` не считать stowed, а отражённое поле `equipMode` внутри post может отставать. Если post наступает до окончания визуального движения, это не подтверждённая точка для hide.

**C — совместимость маски и rollback.** Read-only наблюдать **записи** штатной игры в `bHiddenInGame` только проверенного `HildaCudgel_BP_C.hilda_cudgel_sheath` по минимально обоснованным callable seams; получить положительную проверку доставки инструментирования до вывода «писателей не видел». Снимок `false` сам по себе не доказывает отсутствия writers, а native/direct writes могут обходить reflected hook. Определить, возможно ли обратимое независимое suppress/unmask без вмешательства в `bVisible`, не скрывая held main mesh и не теряя ownership после reload/change pawn. Если независимость доказать нельзя, документировать точный blocker; **не выполнять запись, чтобы её проверить** в этом этапе.

## Метод (без новых предположений о периодичности)

Сначала повторно используй доказанные UE4SS хуки/скрипты из предыдущих веток и существующие исходники, без широкого повторного разбора EXE. Если нельзя проверить нужную границу иначе, подготовь **один минимальный read-only observer** с выборочным логированием по точному текущему pawn/actor/component, последовательностью/временем событий и состоянием `owner/socket/asset/visible/hidden` до/после важных callbacks. Перехватывать события Begin/End и EquipModeChange **только для поставленного вопроса**; SetHiddenInGame наблюдать лишь если метод доставки доказуем и цена/охват ограничены. Результат отсутствия callback при невалидированной доставке не трактовать как отсутствие штатного вызова.

Для **визуальной границы** применить только реально достаточное независимое средство: пользовательское наблюдение или при разрешении краткую запись/кадры с метками, позволяющими сопоставить их с логом. Не утверждать точность до кадра, если нет синхронизации источников. Не вводить изменяющий игру HUD ради диагностики без отдельной необходимости.

Следовать `RUNTIME_TEST_HARNESS.md`: ограничивать **работу на callback и объём лога**, не допускать глобального per-frame поиска; обеспечить управляемую остановку и cleanup, целостную идентичность/hash source+log, защиту от stale pawn. Выбирай длительность/счётчики из реально нужного короткого сценария, а не произвольный жёсткий таймаут, который может прервать естественное игровое действие. Сначала stub/syntax тесты.

**Не запускать, не закрывать и не перезапускать игру без разрешения пользователя.** При готовом observer остановиться и сообщить минимальный игровой сценарий, если разрешения ещё нет. После разрешённого сеанса фиксировать наблюдения как runtime evidence, а не как гарантию универсального поведения.

## Строгие ограничения

**Только исследование/read-only.** Никаких `SetVisibility`, `SetHiddenInGame`, write-test, gameplay mutation, изменения или установки основного мода, VFX, игровых ассетов, сейвов, чужих модов, выпуска версии/CI/release. Не публиковать proprietary game data, полные дампы, raw приватные логи, machine paths и secrets. Не повторять исследование 15 No Scabbard ресурсов. Не расширять автоматически на все типы оружия.

## Критерий остановки и результат

Отчёт `docs/SCABBARD_VISUAL_BOUNDARIES_05.md` должен разделить **статически доказанное / реально наблюдённое / не подтверждённое** и дать по A/B/C ясные выводы, source identity, сценарий, синхронизацию/ограничения визуального наблюдения, объективные условия безопасности и **READY/BLOCKED для одного последующего обратимого write-test на cudgel**. Не выдавать только стоковый `EquipModeChange` за конец анимации и не требовать универсальной поддержки всех оружий для первого узкого теста.

**Стоп:** три границы получили достаточное доказательство для минимального безопасного теста, **либо** найден конкретный нерешённый seam с одним следующим действием; не продолжать автоматически в production или VFX.

Обновить текущий mod-local STATUS только по фактам; новые подтверждённые общие игровые сведения (не меняющееся состояние мода) — в Asterigos-Research с первичной ссылкой. Исследовательская ветка, coherent commit, push, проверка remote SHA. Конечный ответ краткий: ветка, SHA, результат push, A/B/C, READY/BLOCKED и один следующий шаг.
