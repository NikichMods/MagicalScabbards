# MagicalScabbards — VFX Design 01: магическое появление и исчезновение ножен

**Решение:** после стабильного `v0.1.0` пользователь разрешил перейти к отдельному этапу визуальных эффектов (2026-11-19). Ветка `dev/vfx-01`. Стабильный релиз, тег `v0.1.0`, его ZIP/manifest и проверенный hide/show не изменяются. Это дизайн и ограниченная оценка host-сигнала, **не готовая реализация**.

## Цель и визуальная спецификация

| Переход | Визуальное действие | Ориентир длительности |
| --- | --- | --- |
| Ножны возвращаются при начале настоящего draw | Небольшая мягкая золотисто-голубая вспышка / короткий росчерк светящихся частиц непосредственно около ножен; штатная геометрия появляется сразу | ~0,3 с |
| После `3000 мс` подтверждённого stowed ножны скрыты | Небольшой золотисто-голубой след/искры мягкого растворения, маскирующий мгновенный бинарный hide | ~0,4 с |

Эффект фэнтезийно-магический, **не яркий и не неоновый**: без большого магического круга, освещения окружения, полного экрана, постобработки и заметного дыма. Использовать лёгкую короткую локальную частицу или уже существующий подходящий штатный эффект, если доказано, что разрешён его точный consumer в текущем runtime. Не подменять ножны другой геометрией. Разрешается бинарное появление/исчезновение, иллюзия плавности создаётся исключительно отдельным VFX. Предпочтение аккуратности и производительности над сложной красотой.

## Неприкосновенные гарантии v0.1.0

1. Начало реального draw сразу отпускает маску; VFX **никогда не задерживает** `SetVisibility(true)`, не вмешивается в native equipment/animations. Исключить ситуацию, когда эффект маскирует задержку появления ножен.
2. Скрытие — только по существующему правилу `3000 мс` подтверждённого STOWED; VFX не начинает свой независимый отсчёт, не продлевает suppression и не изменяет admission, owner, held/outgoing или rollback.
3. Только после **подтверждённой** действительной смены видимости; ни при обычном sample/poll, ни при failed/probe, повторном census, неполном admission, foreign writer, отсутствии целей или UNKNOWN. Не создавать по одной эмиссии для каждой из 6–7 частей: действие относится к одному убранному комплекту и одной согласованной транзакции.
4. Произвольные stop/reload/EndPlay/fault cleanup не должны порождать волны эффектов или оставлять live emitters. При сомнении пропустить VFX; **сам hide/show и rollback работают без него**. Для выбранного реального draw эффект допускается только при успешном освобождении ранее собственной активной маски.
5. Никаких изменений экипированного оружия в руках, браслетов на запястьях, предметов мира, чужих модов, сохранений, коллизии, HUD, звуков и освещения. Эффект локален по месту крепления актуального sheath-комплекта к Хильде; не привязываться к устаревшему actor.
6. Создаваемый объект VFX, если он понадобится, имеет явно проверенного владельца и конечную lifetime/cleanup-политику; невозможность создать/уничтожить эффекты не должна создавать `CLEANUP_PENDING` у исходных ножен и не должна ломать v0.1.0.

## Проверенная точка интеграции и неустановленная host-часть

- `Scripts/visibility.lua` создаёт собственный lease только после подтверждённого setter; по завершении `mask(...)` сообщает `HIDDEN targets=N`, а `release(reason)` сначала возвращает собственные видимые компоненты, затем сообщает `RELEASED reason`. `Scripts/main.lua` получает `release("draw-pre")` через ранний `BeginDoSkill`; другие причины release включают `stop`, `load-map-pre`, повреждение/смену identity и ошибку.
- Из этих фактов следует **возможная** точка уведомления после успешной транзакции. Однако **лог-событие само по себе не должно становиться gameplay/VFX API**. Рассмотреть один явный необязательный callback с семантикой `confirmed hide` / `confirmed draw release` вместо парсинга текста логов; проверить все callers и влияние на state/rollback до изменения общего `visibility.lua`. Пользовательский effect не нужно запускать для каждой произвольной `RELEASED`.
- Host-effect owner/last writer, точный штатный ParticleSystem/Niagara/особый asset, API создания attached FX, позиция/сокет и надёжное уничтожение/lifetime в установленной сборке UE4.27/UE4SS **ещё не доказаны**. `HildaSoftLight` и общее Asterigos Research дают прецеденты аккуратной работы с собственными компонентами, но **не подтверждают** готовый эмиттер для ножен.
- **Production gate VFX: BLOCKED до host-доказательства**. Нельзя создавать runtime-кандидат только из общего знания Unreal API, случайного asset path или предположения, что SpawnEmitterAttached доступен в данной сборке.

## Локальная проверка 2026-11-19

**Общее доказательство** фиксирует статические UHT-декларации Cascade/Niagara и ссылку штатного Blueprint на `dualoff_fx`. [Asterigos-Research `b43b1b9`](https://github.com/NikichMods/Asterigos-Research/commit/b43b1b92455ea55f63bf309e41d4b5b41d29ac35)

**Статика, Steam 1.09 / build 12996889, UE4.27, UE4SS `83330635`.** Сохранённый штатный UHT-дамп объявляет `UGameplayStatics::SpawnEmitterAttached` (Cascade) и `UNiagaraFunctionLibrary::SpawnSystemAttached`. У обеих функций есть параметры целевого `USceneComponent`, сокета, активации, auto-destroy и pooling. В дампе также есть `USceneComponent::DoesSocketExist`, `UActorComponent::Deactivate` и `K2_DestroyComponent`. Исходники закреплённого UE4SS (`LuaUObject.cpp`, `LuaMod.cpp`) показывают маршалинг отражённых структур из Lua-таблиц, UObject, FName, byte/enum, вызов через `ProcessEvent` и ограничение `LoadAsset` игровым потоком. Это статический маршрут. Вызов конкретного спавнера, полученный объект, владелец и уничтожение в игре ещё не наблюдались. [Контракт вызова UE4SS](https://docs.ue4ss.com/lua-api/classes/ufunction.html) · [Контракт завершения Cascade в справочнике Epic для UE5.8](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UGameplayStatics/SpawnEmitterAttached?application_version=5.8).

**Штатные эффекты.** Cooked-экспорт `HildaDualOff_BP` связывает два шаблона `ParticleSystemComponent` с Cascade `dualoff_fx` в `/Game/MainContent/Assets/fx/bp/skill/hilda/_dual/private/`. Это прецедент штатной оружейной частицы. Длительность, цвет и конечность самого эмиттера из экспорта Blueprint не следуют. В сохранённом каталоге CUE4Parse 1.2.2 есть `general/fire/spark_01` и `skill/hilda_ult/_active/private/ult_active_spark` под `Assets/fx/bp/`. Это имена для поиска, класс, свет, цикл и визуальный масштаб этих ассетов не подтверждены. При повторном чтении текущего каталога Paks существующий reader вернул пустой список и не разрешил `Genesis/AssetRegistry.bin`. Причина не установлена; новые данные самих частиц не получены.

**Транзакции.** В `main.lua` уход ножен можно наблюдать только на успешном возврате `controller.mask`, после записи `maskedIdentity`. Вызывать VFX нужно один раз после подтверждения всех строк, вне setter и обработчиков логов. Для появления одного успешного результата `release(reason)` недостаточно: `visibility.release(reason)` может вернуть `true` при уже видимых или подтверждённо перехваченных чужим writer строках. Для VFX нужен отдельный результат полного собственного восстановления с подтверждённым переходом на исходном комплекте. Активная маска и `draw-pre` сужают точку интеграции, однако общий `BeginDoSkill` охватывает Bracer. Пока нет положительного подтверждения draw конкретного комплекта, его косметическое событие следует пропускать, сохраняя обычный release. Для привязки есть референс `CharacterMesh0` актуальной Хильды и проверяемые в исходной admission цепочки с `scabbard_a` / `scabbard_b`; это кандидат на anchor, а при нескольких mounts выбор локального места требует проверки. Эффект должен переживать hide только на независимо видимом родителе.

| Поле gate | Результат |
| --- | --- |
| Наблюдаемое свойство | Один локальный VFX на подтверждённый hide или draw release, около 0,4 / 0,3 с соответственно. |
| Владелец | Транзакция видимости принадлежит `visibility.lua`. Владелец отдельного созданного VFX на актуальной Хильде в игре не подтверждён. |
| Последняя запись / потребитель | Места после транзакций определены с оговорками выше. Цепочка Lua → spawn → attachment → завершение/удаление для конкретного шаблона не доказана. Auto-destroy привязан к завершению системы и сам по себе не задаёт предел времени. |
| Зона воздействия | Предполагается один отдельный transient-компонент на комплект. Радиус, стоимость, отсутствие источников света и поведение при teardown для конкретной частицы неизвестны. |
| Инварианты | 3000 мс, момент draw, admission, lease, rollback, Bracer и смена через меню остаются на маршрутах v0.1.0. Ошибка VFX должна оставаться внутри косметического компонента. |
| Приёмка | Сначала один отдельный игровой опыт с точным конечным шаблоном на game thread: валидный результат, положение на текущем `CharacterMesh0`, естественное завершение и безопасное снятие при прерывании. После READY — Lua 5.4 для событий/отказов и игровой A/B на комплекте со спиной/поясом и Bracer + ShieldSword. |

**BLOCKED.** Ключевой пробел — подтверждённая пара «конкретный короткий asset → отдельный attached-компонент с конечной жизнью». `SpawnEmitterAttached` — первый маршрут для проверки, потому что в cooked-данных уже найден пример Cascade на оружии. Возобновлять с одного точно идентифицированного one-shot: сначала подтвердить его модули/цикл из метаданных, затем проверить спавн и удаление на текущей Хильде вне событий ножен. Если это сработает, останется проверить семантику настоящего draw для косметического события. Runtime-кандидат и установка в этом этапе отсутствуют.

## Адресная проверка Cascade dualoff_fx

**BLOCKED — нет ключа, который локальный CUE4Parse 1.2.2 принимает для индексов установленного Steam build 12996889.** Ридер распознал `pakchunk0-WindowsNoEditor.pak` и `pakchunk0-WindowsNoEditor.utoc` как зашифрованные контейнеры с индексом. Для обоих `TestAesKey` вернул `false` с нулевым значением и с доступной публичной записью для Asterigos. Смонтировано 0 контейнеров, поэтому точный пакет `/Game/MainContent/Assets/fx/bp/skill/hilda/_dual/private/dualoff_fx` не открылся. Это конкретизирует причину пустого списка при первой проверке. [Правила монтирования CUE4Parse 1.2.2](https://github.com/FabianFG/CUE4Parse/blob/v1.2.2/CUE4Parse/FileProvider/Vfs/AbstractVfsFileProvider.cs)

Сохранённый cooked-экспорт `HildaDualOff_BP` подтверждает ссылку на шаблон Cascade. Данные самого шаблона нужны, чтобы установить конечность эмиссии, длительность, цвет, размер и наличие света. Условие для запуска `SpawnEmitterAttached` пока не выполнено. Создание, положение, естественное завершение и снятие при прерывании на живой Хильде остаются непроверенными. Для возобновления нужен читаемый экспорт модулей именно этого ассета или рабочий доступ к его cooked-пакету.

## Отложено

Непрерывность ножен при menu swap и раздельное распознавание активного Bracer для `BeginDoSkill` сюда не входят. У них отдельный acceptance и риск, их не добавлять в VFX-кандидат. Не выбирать новую публичную версию до появления принятого тестового VFX-кандидата.
