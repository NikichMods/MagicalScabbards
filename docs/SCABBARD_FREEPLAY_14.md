# Свободный игровой сеанс с диагностикой

**scabbard-freeplay-01 · READY офлайн для свободного read-only сеанса · NOT_TESTED в игре · управление видимостью BLOCKED.** Основа `599a1b3`. Исходник [main.lua](../research/scabbard-freeplay-01/observer/Scripts/main.lua), SHA-256 `904a0c46ed7d25e5e8e209987245b773716fa7cadd956dbe42bcf88b7f74eab5`.

## Инженерная граница

Frozen `1c63b62` подтверждён в одном наборе и управляемом сценарии. При смене слота без раннего callback уже активная маска может пережить потерю owner/attachment. `PlayerEquipment.OnSettingEquip` наблюдается через Blueprint **post**, время до изменения креплений не доказано. После потери exact identity восстановление по старому адресу запрещено, а reflected hooks не доказывают владение при прямой native записи. Эти ограничения распространяются на весь сеанс, в котором смену слота можно инициировать в любой момент. Поэтому эта версия не ставит live-масок даже при правильном stock-наборе. Здесь нет скрытого переключателя записи. Проверенный write-кандидат остаётся историческим артефактом для своего ограниченного протокола.

Единый observer использует exact-группу и состояния stock cudgel из frozen-кандидата, уведомление из `636bf22`, события skill, режима, reflected setters и lifecycle. Теневая двухсекундная логика использует штатный game-thread timer и проверяет актуальное поколение, шесть целей, состояние skill и stock-флаги. При expiry только логируется `SHADOW_HIDE`, без вызова setter. Late Sheath и отмена таймера учитываются в тени. Успех тени не подтверждает визуальное скрытие.

Состояния: idle/stopped, recovering после границы поколения, diagnostics_only, cleanup_pending. Ошибка одного callback инвалидирует текущий таймер и пару writer, оставляя наблюдение активным. LoadMap/EndPlay выбрасывают сохранённый контекст, а вышедший pawn отвергается при повторной привязке. Перепривязка выполняется на событиях и по ручному START, без per-frame polling. Если Build не доставляет LoadMap post или следующего распознаваемого события нет, START повторно снимает контекст в том же сеансе. Сохраняются строки идентичности, объекты разрешаются заново. Закрытие таймера защищено token и epoch. Если отмена не подтверждена, диагностика продолжается, новый таймер блокируется. STOP снимает reflected hooks, повторный START разрешён после CLEANED. Глобальные lifecycle callbacks и клавиши остаются зарегистрированными, но lifecycle callbacks инертны при остановке.

## Один свободный сеанс после отдельного разрешения

При закрытой игре оставить активным только `scabbard-freeplay-01` среди кандидатов MagicalScabbards. **Ctrl+Alt+F7** — START. **Ctrl+Alt+F8** — STOP. Голые F4/F7 использует активный StaffRebalanceFireRateProbe. Регистрация сочетаний проверяется повторно при загрузке. Нажимать START можно и до появления Хильды, при необходимости один повторный START обновляет привязку. Затем играть в удобном порядке, включая смену слотов и сохранение/загрузку. Видимость в этом observer полностью штатная. STOP перед выходом даёт определённый итог, при завершении процесса без STOP маркер CLEANED не обещается.

| Сценарий | Достаточное наблюдение |
| --- | --- |
| Draw, InHand, stow, overlap | `SKILL`, `EQUIP_POST` и reflected `WRITER`; при корректном stow `SHADOW_SCHEDULE`, при новом draw `SHADOW_CANCEL` без expiry отменённого токена, при позднем Sheath возможен `SHADOW_SHEATH_SKIP`. |
| Изменение слота | `SETTING_EQUIP_POST` и `TARGET stage=old-at-post/current-at-post`. `exact=false` или `same=false` у старой цели означает, что прежний exact guard уже не пропускает rollback. Совпадение оставляет открытым порядок относительно начала фактической мутации. |
| Reload или новый pawn | `BOUNDARY`, отмена старого shadow token, затем новая `GENERATION` при доставленной точке перепривязки. |
| STOP и повторный START | `CLEANED writes=0`, следующий START с новым epoch. При `CLEANUP_PENDING` новый сеанс заблокирован до очистки. |

`PASS` означает только конкретно подтверждённое действие диагностики, например отмену shadow timer. `OBSERVED_ONLY` — событие принято, `SKIPPED_UNSAFE` — нет разрешения на запись или отсутствует guard, `FAIL` — ошибка диагностической операции. Невосстановленных игровых масок у этой сборки быть не может, поскольку она их не устанавливает. `CLEANUP_PENDING` здесь относится к таймеру или хуку и не выдаётся за успешный STOP.

Lua 5.4: длинная последовательность в одном сеансе, повторный Sheath, отмена и stale expiry, отказ на изменённой цели, событие слота, reflected writer, новая identity после LoadMap, STOP/START, ошибка отмены и 30 циклов повторного запуска. Ноль записей. Частичная запись и невозможность отката относятся к frozen write-кандидату и уже покрыты его стабами. Реальная доставка equipment/lifecycle callbacks этой сборки ещё не проверена.

## Игровой сеанс 2026-11-08

Кандидат `f405b16a41f6c95ba657c5bde5a6aaee10af779c`, хэш установленного Lua совпал. Приватный журнал SHA-256 `70d24b6931120045433ce7753a74e18f43fa068cb83673debb184f2e2d97a97a`.

- **Смена слота:** дважды `BOUNDARY reason=equipment-end-play` предшествовал первому `SETTING_EQUIP_POST` примерно на 1,5 мс. Новый поиск в обоих post не нашёл подходящего sheath. После возврата прежнего набора найден каждый раз другой экземпляр молота. Для наблюдавшегося маршрута Blueprint post не годится для восстановления всей старой группы. EndPlay раньше post, но безопасный release в самом EndPlay не доказан.
- **Предел отчёта:** EndPlay сбрасывает старый snapshot до post. Строки `old-at-post exact=false same=false` сразу после этой границы означают отсутствие сохранённой привязки, поэтому не доказывают исчезновение всех шести целей. Вывод опирается на порядок событий, отсутствие подходящего sheath при новом поиске и смену его экземпляров.
- **Загрузка:** зафиксирован `load-map`. Пока HUD отсутствовал, сработали guards, но сеанс не остановился. После появления другого HUD/pawn в том же epoch записан `GENERATION` и новый `SHADOW_HIDE writes=0`.
- **Таймер и STOP:** наблюдалась `SHADOW_CANCEL reason=draw`; вручную завершено `CLEANED writes=0`, игра закрылась штатно. Повторный START в этом журнале не проверен.

Read-only наблюдение смены слота и восстановления диагностики после reload подтверждено. Live hide и rollback при смене слота остаются BLOCKED. Следующий технический вопрос — найти событие до потери старой привязки, не повторяя наблюдение уже проверенного позднего post.
