# MSVfxBrowser01 — отдельный просмотрщик штатных частиц

**Статус:** первый игровой просмотр выполнен на `ba34a97`, пользователь выбрал №02. Регулировка масштаба прошла Lua 5.4, игровой результат исправленной раскладки ожидается. Тестовая `0.1.1-test.1` и выпущенная `v0.1.0` неизменны.

## Управление

| Клавиша | Действие |
| --- | --- |
| **`F2`** | Уменьшить масштаб на 0,05 и повторить текущий эффект. |
| **`F3`** | Увеличить масштаб на 0,05 и повторить текущий эффект. |
| **`F7`** | Следующий кандидат и его воспроизведение; после последнего — снова №1. При первом F7 выбирается №1. |
| **`F6`** | Предыдущий кандидат и его воспроизведение; перед №1 — последний. При первом F6 выбирается последний. |
| **`F9`** | Повторить выбранный эффект, **не меняя номер**. При первом F9 выбирается №1. |

Все клавиши работают **без Ctrl и Alt**. Диапазон масштаба — 0,10–0,60, начальное значение — 0,40. Масштаб сохраняется в пределах сеанса при переходе по каталогу. Если нажать F2/F3 до выбора, открывается №1. Собственный эмиттер завершается автоматически или принудительно watchdog (1600 мс); перед повтором или переключением предыдущий собственный эффект очищается. Экранная подпись показывает текущий масштаб. Каталог пересоздаётся при загрузке новой карты или после перезапуска игры; отдельная клавиша закрытия браузера не нужна. Номер, масштаб и точный UObject path сохраняются в логе.

На отдельном экране UMG показывается `NN/TT  name  PLAY/SKIP`. В `UE4SS.log` записываются `[MSVfxBrowser01] CATALOG / ENTRY / SELECT / PLAY / SKIPPED / CLEANED / UI_*` с точными UObject paths. При записи короткого видео номер и имя останутся видны. Если экранный host не заработает, сообщения останутся в логе — **это непроверенный runtime-случай, а не заранее объявленный UI PASS**.

**Конфликт F5, 2026-11-20.** На `b7172bf` активный редактор `ImmersiveInteractionPromptsNativeWorldQuintus` занял обычную F5, и браузер завершил инициализацию до регистрации управления. Масштаб перенесён на F2/F3. Если пара занята, браузер пишет `SCALE_UNAVAILABLE` и сохраняет F6/F7/F9. Настройки и клавиши редактора не менялись.

## Откуда кандидаты

Первые **шесть** записей — известные пакетные источники из [каталога в VFX_DESIGN_01](../../docs/VFX_DESIGN_01.md#каталог-для-визуального-просмотра): `throw_spark_astral`, `stf01_spark`, `spark_01`, `ult_active_spark`, `astral_hit_01`, `astral_missile_shoot` (последний намеренно оставлен отрицательным контролем). **Точный объект `astral_missile_shoot` подтверждён ранее; у остальных путь UObject выведен из доказанного имени пакета, но ещё не проверен.** Если `LoadAsset` его не находит или это не `ParticleSystem`, элемент безопасно помечается `SKIP`, без спавна.

При первом открытии скрипт **один раз** вызывает `FindAllOf("ParticleSystem")` и добавляет к шести исходным вариантам уже загруженные в процессе `spark/glint/shimmer/flash/twinkle` из `/Game/MainContent/Assets/fx/bp/`. Они сортируются и дедуплицируются; максимум **20 записей всего**, не 20 гарантированно доступных эффектов. При другом наборе загруженных игровых ресурсов число и порядок динамических записей может измениться. В этом случае обязательно сохранять **полный UObject path из лога**, а не только номер. Никакого обхода зашифрованных контейнеров, asset dump, автоматической загрузки сотен ресурсов, произвольных классов или сохранения состояния в настройках.

## Принципы безопасности

- Отдельная папка мода, не подключённая к рабочему `MagicalScabbards`; штатная видимость ножен **не меняется**.
- Каждое нажатие обрабатывает одну запись. Только при успешном exact `ParticleSystem` lookup и консервативной проверке `EmitterLoops == 1` и `0 <= EmitterDuration <= 2.5` для всех включённых LOD выполняется `SpawnEmitterAttached` на проверенном `CharacterMesh0:scabbard_b` (запасной `scabbard_a`), с выбранным масштабом. Бесконечные и непроверенные шаблоны пропускаются.
- Перед новым эффектом предыдущий **собственный** PSC удаляется; watchdog до 1600 мс, auto-destroy и отдельный cleanup при смене карты (и закрытии игры). При неподтверждённом удалении дальнейшие спавны блокируются до перезапуска. Никаких изменений stock templates/CDO, системных Niagara/FX, чужих виджетов или игровой логики.
- Экранная надпись создаётся как собственный `PostionItemUMG_BP_C` с собственным `TextBlock`, по уже подтверждённому в этой сборке [UI-прецеденту IIP](https://github.com/NikichMods/ImmersiveInteractionPrompts/blob/6e9ebddafeeb1bb68a089e280c1a2f89b99924a8/research/interaction-prompts-owner/userwidget-host/probe/README.md). Не используется debug PrintString, который может не работать в Shipping; исходный HUD не меняется. Для этой новой многократной эксплуатации отдельный runtime lifecycle gate ещё открыт.
- Визуальные размеры, наличие в эффекте света/дыма, finite-loop readback, работа всех клавиш и гарантии удаления при активной частице **не подтверждены в игре для этого viewer**. Первая игровая проверка должна быть ограниченной и останавливаться при `FAILED` / `CLEANUP_PENDING`. Не объявлять 20 визуально безопасными заранее.

## Установка/проверка — только после локальной ревизии Codex

1. При закрытой игре убедиться, что прежние **исследовательские** `MSStockVfxFade01`, `MSVfxLoadProbe01`, старые UI-probe и их hotkeys отключены. Особенно убедиться, что **обычные `F6`, `F7` и `F9` без модификаторов свободны**; при обнаруженном конфликте UE4SS-регистрации браузер отказывается включаться. Не выключать чужие игровые моды по умолчанию; при конфликте остановиться и сообщить.
2. Скопировать **оба** файла `Scripts/main.lua`, `Scripts/catalog.lua` в отдельную папку `<UE4SS>/Mods/MSVfxBrowser01/Scripts/`, рядом создать пустой `enabled.txt`. Исходники фиксируются полными SHA256 до копирования. Сохранять контрольные хэши остальных файлов/модов.
3. Войти в управляемую Хильду, закрыть меню. Чтобы нужные эффекты были в памяти, использовать штатные магические атаки/заклинания и затем переключать эффекты F6/F7 и повторять текущий F9. Для нового снимка уже загруженных эффектов нужна смена карты или перезапуск игры (сканирование один раз на каталог). Отсутствие ресурсов в памяти не является дефектом их пакетов.
4. Просмотреть интересующие кандидаты, сохраняя видео с видимой надписью. Если экранная подпись не видна, фиксировать точные `SELECT/PLAY` и номер из UE4SS.log; не пытаться править штатный HUD во время теста. Для кандидата `SKIP` нет визуального результата.
5. После просмотра закрыть игру, убрать только исследовательский `enabled.txt` (или папку), проверить штатное поведение `v0.1.0`. Держать `0.1.1-test.1` неизменным, не переименовывать его ZIP.
6. Передать только хэши/проверяемые диагностические строки/номера и выбранные полные пути; пользовательское видео остаётся локальным или прикрепляется в чат, не коммитится в GitHub.

**Приёмка первого запуска:** читаемый каталог/имя на экране; успешные F7 (следующий), F6 (предыдущий) и F9 (повтор без смены номера) на хотя бы двух безопасных конечных экземплярах; `SKIP` для не найденных/looping; cleanup после следующего эффекта и смены карты; сохранность базовых ножен и отсутствие ошибок UE4SS. Дальше можно расширять список через реальный локальный `all-paths.txt`, **только после точной проверки дополнительных package paths**. Не выводить 20 искусственных ассетов.

**Локальный preflight 2026-11-20 — BLOCKED на обычной F7.** Проверен исходник `ba34a97` на целевой установке Steam build `12996889` и UE4SS `83330635`. Обе Lua-части прошли проверку синтаксиса и каталога. Модель инициализации с настоящим модулем каталога подтвердила регистрацию F6/F7/F9 без модификаторов при свободных клавишах и отказ до регистрации любой клавиши при занятой F7. В последнем игровом логе установленный и включённый `StaffRebalanceDev` подтвердил `F7=stop`. В проверенных активных исходниках других обычных F6/F9 не найдено. У `OutfitCheatMod` есть F6, но мод выключен. Активная привязка F9 у `ImmersiveInteractionPromptsNativeS1` использует Ctrl+Alt. `DualoffFxSnapshot` использует Ctrl+Alt+F11, ручная `MSStockVfxFade01` уже выключена, `MSVfxLoadProbe01` отсутствует. Установленные моды и настройки оставлены в исходном состоянии. Папка браузера не создана.

**Установка после разрешения пользователя.** При закрытой игре маркер `StaffRebalanceDev/enabled.txt` перенесён в резервную папку вне `Mods`. Браузер установлен отдельно в `MSVfxBrowser01` с пустым `enabled.txt` и обоими Lua-файлами побайтно из `ba34a97`. Контрольные хэши остальных 59 файлов в `Mods` совпали до и после операции. После просмотра при закрытой игре убрать маркер включения браузера и вернуть сохранённый маркер StaffRebalanceDev. Игра не запускалась, остаётся проверить фактическую регистрацию клавиш, экранную подпись и воспроизведение.

## Дальнейший шаг

**Игровой просмотр 2026-11-20.** На UE4SS `83330635` подтверждены `ARMED`, `UI_READY`, каталог из 20 позиций, переходы вперёд и назад и повтор выбранного номера. 10 разных позиций дали `PLAY`, другие 10 дали `SKIPPED`: хотя бы один проверенный RequiredModule не удовлетворил `EmitterLoops == 1`. Журнал содержит очистку при переключении и watchdog, без `FAILED` или `CLEANUP_PENDING` в наблюдаемом фрагменте браузера. Смена карты с живой частицей или виджетом отдельно не подтверждена.

**Выбор пользователя — №02 Staff cast spark.** Повторный `PLAY` на `scabbard_b` при масштабе `0.40`, два включённых LOD прошли проверку. Точный UObject — `/Game/MainContent/Assets/fx/bp/skill/hilda_ult/_stf01/private/stf01_spark.stf01_spark`. На пользовательском кадре видны тонкие синие искры с широким разлётом, голубой засветкой одежды и пола. Продолжительность и источник засветки по одному кадру неизвестны. Отбирать этот шаблон для адресной проверки масштаба, света и доступных параметров экземпляра. Определять их по самому `stf01_spark`, поскольку параметры прежнего `astral_missile_shoot` к нему автоматически не применяются.

Снимок журнала SHA-256 `7471efb3c9c6a559065e5620ac5c10dbb433d98584a63de6f43fb677a9b84fb7`. Пользовательский кадр SHA-256 `01e4e61ea081a533821f71c1b3e3703c072ec886730b8385326e830c1f9d2ffb`. Исходный кадр и выдержка из лога сохранены локально.

После выбора одного или двух **визуально пригодных** коротких искристых эффектов — определить их точную локальную область/эмиттер и возможность распределения вдоль жёстких ножен. Не считать успешный просмотр доказательством, что можно менять stock origin, count или particle shape без custom cook. Если нужного класса частиц среди штатных нет — вернуть решение по собственному UE4.27 Niagara после решения Windows cooker/mount blocker.

Это самостоятельная исследовательская проба без номера `0.1.1-test.2` и без установочных release assets.
