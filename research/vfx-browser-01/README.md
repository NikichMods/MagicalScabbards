# MSVfxBrowser01 — отдельный просмотрщик штатных частиц

**Текущий исходник:** F4 и NumPad подтверждены на `6af4a91`. В следующем кандидате изменение параметров №02 применяется к ручному предпросмотру и следующему автоматическому эффекту исчезновения. Передача между модами проверена офлайн, игровой прогон ожидается.

## Управление

| Клавиша | Действие |
| --- | --- |
| **F4** | Открыть режим на №02 **Staff cast spark** и показать эффект. Повторное F4 закрывает режим и очищает собственный предпросмотр. |
| **NumPad 4 / 6** | Предыдущий / следующий эффект и воспроизведение. До 20 записей в зависимости от загруженных ресурсов. |
| **NumPad 7 / 9** | Сильнее / слабее замедлить №02 по ступеням 0,2 / 0,3 / 0,5. |
| **NumPad 1 / 3** | Уменьшить / увеличить время удаления №02 на 0,25 с в диапазоне 0,25–3,00 с. |
| **NumPad 2 / 8** | Уменьшить / увеличить вход `Color` у №02. Ступени: штатный → 0,75 → 0,50, с повтором эффекта после изменения. |
| **F2 / F3** | Уменьшить / увеличить масштаб на 0,05 в диапазоне 0,10–0,60. |
| **F9** | Повторить текущий эффект. |

Использовать NumPad с включённым Num Lock и без модификаторов. Кроме F4, клавиши действуют только в открытом режиме. Изменения масштаба, замедления и времени удаления повторяют выбранный эффект. При смене карты режим закрывается. Коллизия клавиши отключает соответствующую пару. При занятой F4 режим недоступен. Во время просмотра панель редактора HildaSoftLight должна быть закрыта, так как она опрашивает те же физические клавиши через PlayerController.

Новый дефолт №02 выбран по игровому журналу и скриншоту `6af4a91` — масштаб **0,60**, `CustomTimeDilation=0.5`, cutoff **1,50 с**. Штатный свет сохраняется. Изменение масштаба, темпа или cutoff №02 пишет `SETTINGS_SHARED`. Другие записи используют отдельный масштаб и исходные темп и watchdog 1600 мс. Экранная подпись и журнал показывают номер и параметры, журнал содержит точный путь. Значения в памяти сбрасываются при перезапуске игры.

### A/B для Color №02

Открыть F4 и сравнить в одной точке и с одинаковым ракурсом: **штатный → 0,75 → 0,50 → штатный**. NumPad 2 идёт вниз, NumPad 8 возвращает к штатному. Сравнить видимость искр и синюю засветку земли по отдельности. Масштаб, скорость и cutoff в этой серии держать одинаковыми.

Штатная ступень воспроизводит новый компонент без записи `Color`. Две другие ступени перед активацией записывают одинаковые X/Y/Z через `SetVectorParameter` и проверяют тип и все три канала в `InstanceParameters`. Запись разрешена после подтверждения точного stock `ColorScaleOverLife` с именованным векторным параметром `Color` в обоих активных эмиттерах и каждом включённом LOD. `COLOR_MAPPING` печатает `Constant`, входные/выходные диапазоны и доступные `ParamModes`. `COLOR_SET` подтверждает только запись и чтение инстансного значения. Число на экране означает вход RGB, который может быть перенормирован распределением. Световой модуль и `Fade` сохраняют штатные параметры. Эта настройка применяется только в браузере, остальные параметры №02 по-прежнему передаются автоматическому эффекту.

На отдельном экране UMG показывается `NN/TT  name  PLAY/SKIP`. В `UE4SS.log` записываются `[MSVfxBrowser01] CATALOG / ENTRY / SELECT / PLAY / SKIPPED / CLEANED / UI_*` с точными UObject paths. При записи короткого видео номер и имя останутся видны. Если экранный host не заработает, сообщения останутся в логе — **это непроверенный runtime-случай, а не заранее объявленный UI PASS**.

**Конфликт F5, 2026-11-20.** На `b7172bf` активный редактор `ImmersiveInteractionPromptsNativeWorldQuintus` занял обычную F5, и браузер завершил инициализацию до регистрации управления. Масштаб перенесён на F2/F3. Если пара занята, браузер пишет `SCALE_UNAVAILABLE` и сохраняет F6/F7/F9. Настройки и клавиши редактора не менялись.

## Откуда кандидаты

Первые **шесть** записей — известные пакетные источники из [каталога в VFX_DESIGN_01](../../docs/VFX_DESIGN_01.md#каталог-для-визуального-просмотра): `throw_spark_astral`, `stf01_spark`, `spark_01`, `ult_active_spark`, `astral_hit_01`, `astral_missile_shoot` (последний намеренно оставлен отрицательным контролем). **Точный объект `astral_missile_shoot` подтверждён ранее; у остальных путь UObject выведен из доказанного имени пакета, но ещё не проверен.** Если `LoadAsset` его не находит или это не `ParticleSystem`, элемент безопасно помечается `SKIP`, без спавна.

При первом открытии скрипт **один раз** вызывает `FindAllOf("ParticleSystem")` и добавляет к шести исходным вариантам уже загруженные в процессе `spark/glint/shimmer/flash/twinkle` из `/Game/MainContent/Assets/fx/bp/`. Они сортируются и дедуплицируются; максимум **20 записей всего**, не 20 гарантированно доступных эффектов. При другом наборе загруженных игровых ресурсов число и порядок динамических записей может измениться. В этом случае обязательно сохранять **полный UObject path из лога**, а не только номер. Никакого обхода зашифрованных контейнеров, asset dump, автоматической загрузки сотен ресурсов, произвольных классов или сохранения состояния в настройках.

## Принципы безопасности

- Отдельная папка мода, не подключённая к рабочему `MagicalScabbards`; штатная видимость ножен **не меняется**.
- Каждое нажатие обрабатывает одну запись. Только при успешном exact `ParticleSystem` lookup и консервативной проверке `EmitterLoops == 1` и `0 <= EmitterDuration <= 2.5` для всех включённых LOD выполняется `SpawnEmitterAttached` на проверенном `CharacterMesh0:scabbard_b` (запасной `scabbard_a`), с выбранным масштабом. Бесконечные и непроверенные шаблоны пропускаются.
- Перед новым эффектом предыдущий **собственный** PSC удаляется; watchdog до 1600 мс, auto-destroy и отдельный cleanup при смене карты (и закрытии игры). При неподтверждённом удалении дальнейшие спавны блокируются до перезапуска. Никаких изменений stock templates/CDO, системных Niagara/FX, чужих виджетов или игровой логики.
- Экранная надпись создаётся как собственный `PostionItemUMG_BP_C` с собственным `TextBlock`, по уже подтверждённому в этой сборке [UI-прецеденту IIP](https://github.com/NikichMods/ImmersiveInteractionPrompts/blob/6e9ebddafeeb1bb68a089e280c1a2f89b99924a8/research/interaction-prompts-owner/userwidget-host/probe/README.md). Не используется debug PrintString, который может не работать в Shipping; исходный HUD не меняется. Для этой новой многократной эксплуатации отдельный runtime lifecycle gate ещё открыт.
- Визуальные размеры, наличие в эффекте света/дыма, finite-loop readback, работа всех клавиш и гарантии удаления при активной частице **не подтверждены в игре для этого viewer**. Первая игровая проверка должна быть ограниченной и останавливаться при `FAILED` / `CLEANUP_PENDING`. Не объявлять 20 визуально безопасными заранее.

## История установки и проверок прежней раскладки

В этом разделе F6/F7/F9 и F10/F11 описывают старые версии.

1. При закрытой игре убедиться, что прежние **исследовательские** `MSStockVfxFade01`, `MSVfxLoadProbe01`, старые UI-probe и их hotkeys отключены. Особенно убедиться, что **обычные `F6`, `F7` и `F9` без модификаторов свободны**; при обнаруженном конфликте UE4SS-регистрации браузер отказывается включаться. Не выключать чужие игровые моды по умолчанию; при конфликте остановиться и сообщить.
2. Скопировать **оба** файла `Scripts/main.lua`, `Scripts/catalog.lua` в отдельную папку `<UE4SS>/Mods/MSVfxBrowser01/Scripts/`, рядом создать пустой `enabled.txt`. Исходники фиксируются полными SHA256 до копирования. Сохранять контрольные хэши остальных файлов/модов.
3. Войти в управляемую Хильду, закрыть меню. Чтобы нужные эффекты были в памяти, использовать штатные магические атаки/заклинания и затем переключать эффекты F6/F7 и повторять текущий F9. Для нового снимка уже загруженных эффектов нужна смена карты или перезапуск игры (сканирование один раз на каталог). Отсутствие ресурсов в памяти не является дефектом их пакетов.
4. Просмотреть интересующие кандидаты, сохраняя видео с видимой надписью. Если экранная подпись не видна, фиксировать точные `SELECT/PLAY` и номер из UE4SS.log; не пытаться править штатный HUD во время теста. Для кандидата `SKIP` нет визуального результата.
5. После просмотра закрыть игру, убрать только исследовательский `enabled.txt` (или папку), проверить штатное поведение `v0.1.0`. Держать `0.1.1-test.1` неизменным, не переименовывать его ZIP.
6. Передать только хэши/проверяемые диагностические строки/номера и выбранные полные пути; пользовательское видео остаётся локальным или прикрепляется в чат, не коммитится в GitHub.

Дальше можно расширять список через реальный локальный `all-paths.txt`, **только после точной проверки дополнительных package paths**. Не выводить 20 искусственных ассетов.

При первом воспроизведении точного `stf01_spark` браузер один раз читает модули включённых LOD и пишет `STAFF_MODULE` / `STAFF_DISTRIBUTION` в лог. Отражённый `CustomTimeDilation` масштабирует шаг времени всего компонента и может замедлить движение, одновременно растягивая жизнь и затухание. Сам по себе он не уменьшает итоговый разлёт. **Ожидаемое поведение, не доказанный игровой результат:** UE4.27 [ParticleSystemComponent custom_time_dilation](https://dev.epicgames.com/documentation/en-us/unreal-engine/python-api/class/ParticleSystemComponent?application_version=4.27) масштабирует симуляционный `Tick DeltaTime`. Сочетание этого масштаба с отдельным watchdog через 1000 мс должно ограничить накопленное время перемещения, если GPU-эмиттер `stf01_spark` действительно использует этот временной шаг. Отдельные GPU и векторное поле могут иметь особые зависимости, поэтому **нужно видео A/B при 0.2/0.3/0.5 с одинаковыми масштабом 0.60 и ракурсом**. Таймер `ExecuteInGameThreadWithDelay(1000)` не объявлять физически точным wall-clock дедлайном при паузах/лагах. Проверить, что эффект не обрывается резко, искры остаются заметными, освещение сохранено, а соседние позиции каталога не меняют длительность. Не допускать этих изменений в `Scripts/vfx.lua` / production до игровой приёмки.


**Исследовательская настройка cutoff (2026-11-20).** По запросу пользователя фиксированное `1000 мс` заменено независимым сеансовым `cutoffMsStaff`: **F10 −250 мс**, **F11 +250 мс**, диапазон **250–3000 мс**, старт **1000 мс**. Настройка применяется **только к №02** при следующем создании собственного `ParticleSystemComponent`, удерживается при F9, F4 и переходах по каталогу. Изменение cutoff само повторяет тот же №02. Не пишем данные в настройки или сохранение игры, не меняем `CustomTimeDilation` и световой эмиттер. В `UI` строка `cutoff=0.25s`…`3.00s`, журнал `CUTOFF_SET` и `PLAY … cutoff_ms=…`. Пара клавиш необязательна: при конфликте F10/F11 отключается только управление cutoff, не вся программа. Оффлайн-проверка Lua/mocks и CI не доказывают точность реального таймера, GPU-замедление или качество исчезновения; сравнить короткий и длинный cutoff на одном масштабе `0.60` и выбранном rate, при одинаковом ракурсе. Не считать `autoDestroy` или delayed callback гарантией того, что частицы отобразятся весь интервал; если ресурс завершился ранее, не создавать лишних эффектов.
